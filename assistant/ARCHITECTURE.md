# Ассистент студии: архитектура

## 1. Две плоскости, которые нельзя смешивать

```
            ┌──────────────── ЧАТ-ПЛОСКОСТЬ (синхронно, ≤12 с) ────────────────┐
 браузер ──►│ POST /api/assistant/chat                                          │
            │   router (regex, 0 ток.) ─► recommend / params / errors / ui_help │
            │                     └─► только при выборе модели:                 │
            │                         LLMChain: Groq ─► OmniRoute ─► шаблон     │
            └──────────────┬───────────────────────────────────────────────────┘
                           │ ответ: reply + chips + generate_{model,prompt,params}
                           ▼   (форма заполнена, генерация НЕ запущена)
 пользователь жмёт «Сгенерировать»
                           │
            ┌──────────────▼──── ПЛОСКОСТЬ ГЕНЕРАЦИИ (асинхронно, минуты) ─────┐
            │ POST /api/generate → 202 + job_id → Redis inbound → dispatcher   │
            │   → очередь канала replicate | fal | omniroute → channel_worker  │
            │   billing.hold → провайдер → capture / release                   │
            │ GET /api/generate/jobs/<id> (poll)                                │
            └──────────────────────────────────────────────────────────────────┘
```

**Главное правило:** ассистент ничего не запускает и денег не тратит. Он заполняет форму.
Генерацию запускает только отдельный `POST /api/generate` по кнопке. Биллинг, модерация,
rate-limit и выбор канала остаются в плоскости генерации, у них один источник правды.

## 2. Где LLM, а где нет

| Задача | Как | Токены |
|---|---|---|
| тип задачи, потребности, тема | regex `router.py` | 0 |
| подбор ≥2 моделей, ссылки на витрину | `recommend.py` + карточки + `price_fn` + `health_fn` | 0 |
| параметры (9:16, 10 с, 4k) | `params.py`, только белый список карточки | 0 |
| ошибки, задержки, деньги | `errors.py` по `context` из UI | 0 |
| интерфейс, оффтоп, приветствие, безопасность, инъекции | шаблоны | 0 |
| **переписать идею под модель** | `LLMChain` → JSON `{prompt, note}` | ~350 вход + ≤220 выход |
| правка промпта («сделай теплее») | то же самое, с `prev_prompt` и `change` | ~400 + ≤220 |

На одну генерацию обычно уходит 1–2 вызова LLM, примерно 600–1200 токенов. Прежний `/api/chat`
отправлял каталог на 9000 символов (~3000 токенов) в **каждом** сообщении.

## 3. Как OmniRoute и модели генерации влияют друг на друга

1. **OmniRoute общий для чата и генерации.** Через него идёт LLM ассистента, и он же канал
   генерации `omniroute` (модели `assistant`, `omni-auto`, `omni-auto-free`). Если чат-трафик выберет
   лимиты бесплатных маршрутов, просядут текстовые генерации, и наоборот.
   → Для ассистента по умолчанию **сначала Groq**, OmniRoute идёт вторым (`ASSIST_LLM_ORDER=groq,omniroute`).
   Для чата лучше завести отдельный ключ или combo в OmniRoute (`ASSIST_OMNIROUTE_MODEL`).
2. **OmniRoute на той же VM, что и gunicorn.** Когда OmniRoute нагружен, он отнимает CPU и RAM
   у Flask, и чат с генерацией тормозят одновременно.
   → У LLM жёсткие таймауты (7 с и 5 с) и общий дедлайн 12 с. Circuit breaker держит упавший
   провайдер выключенным 60 с. `max_tokens=220`.
3. **Коррелированный отказ Replicate.** Старый `/api/chat` в крайнем случае звал DeepSeek на Replicate.
   Когда падает Replicate, падают и генерации, и чат, причём именно тогда, когда пользователю
   нужно объяснение. → В цепочке ассистента Replicate **нет**. Последний уровень — шаблонный промпт
   (degraded), он работает всегда.
4. **Состояние каналов влияет на советы.** `health_fn(model)` смотрит `is_channel_healthy` основного
   канала модели и резерва (fal). Модели с мёртвым каналом не предлагаются. Если пользователь всё же
   выбрал такую модель, он увидит «недоступна» и 2 похожие. Если Redis с health недоступен,
   каталог не прячется (fail-open): лучше предложить модель, чем показать пустоту.
5. **Цена.** В чате цена из `_integration_prices()` носит **справочный** характер. Списывает только
   `/api/generate` (hold → capture) по своей цене. Если курс изменился между чатом и запуском,
   прав `/api/generate`.
6. **Переключение на fal при падении Replicate (B2).** Ассистент об этом узнаёт из `context.job_status=requeued`
   или `job_failover=true` и отвечает: «переключили на резервный, цена та же». Когда B2 будет сделан,
   в `INTEGRATED_MODELS` нужно проставить `fallback_provider: "fal"`, и тогда `health_fn` начнёт
   учитывать резерв.

## 4. Что может сломаться и что увидит пользователь

| Сбой | Где ловим | Что видит пользователь |
|---|---|---|
| OmniRoute 429 / висит / 5xx | `LLMChain` → breaker → Groq | ничего, ответ от Groq |
| Groq и OmniRoute оба лежат | `LLMUnavailable` → `fallback_prompt` | промпт = его текст + стиль, пометка «упрощённый режим» |
| LLM вернула не JSON, `<think>`, болтовню | `parse_json_object` + `validate_output` + 1 повтор | ничего |
| LLM вернула небезопасный промпт | `note=unsafe` или regex на выходе | «С этим помочь не могу» |
| Инъекция в тексте («ignore instructions») | router до LLM; в LLM текст идёт как JSON-данные | «Я помогаю только с генерациями» |
| Бюджет токенов сессии исчерпан | `token_budget` / `max_llm_calls` | шаблонный промпт |
| Redis упал | `RedisStore` глотает ошибки | ассистент без памяти: подбор работает, «ещё варианты» может повториться |
| Карточка модели не совпадает с `INTEGRATED_MODELS` | `build_from_env` фильтрует + warning в лог | модель не предлагается |
| Параметр не поддерживается моделью | `params.fit` / `params.validate` | параметр не отправляется; длительность подгоняется к ближайшей с сообщением |
| **Старый фронт стартует генерацию, увидев `generate_prompt`** | `legacy_autostart=True` | без явного «запускай» `generate_*` не отдаются, только `draft_*` |
| Исключение в обработчике | `try/except` в `handle` | «Что-то пошло не так» + «Повторить», HTTP 200 |
| Поток gunicorn занят LLM | дедлайн 12 с < timeout gunicorn 60 с | — |
| Задание долго в `queued`/`running` | `errors.explain` по `job_age_sec` | «в очереди / дольше обычного, деньги только за результат» |
| `insufficient_funds` / 401 / 429 / `free_limit` | `errors.classify` | понятный текст + «Пополнить» / «Войти» / «Модель дешевле» |

## 5. Потоки и память

* Один `Assistant` на воркер. В gthread запросы идут параллельно: учёт LLM лежит в `threading.local`,
  у breaker есть lock. Есть тест на 16 потоков × 100 сессий.
* Сессия в Redis `assist:sess:{user|anon}:{cookie-uuid}`, TTL 6 ч. Храним состояние подбора,
  а не переписку: LLM не нужна история.
* `session_id` из тела запроса **игнорируется**, ключ берётся из cookie-сессии Flask, так чужую сессию не прочитать.
* Breaker живёт в процессе: у каждого воркера свой. Для 3 воркеров это приемлемо, худший случай —
  3 лишних запроса к упавшему провайдеру в минуту.

## 6. Метрики

`on_event` получает `{intent, lang, llm_used, provider, tokens, degraded, ms}`. Адаптер пишет
`assistant_metrics` (total, without_llm) и строку в лог. Нормальная доля ответов без LLM — больше 70 %.
