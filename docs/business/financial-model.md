### Как читать цифры

| Термин | Значение |
|--------|----------|
| **MAU** | *Monthly Active Users* — **число уникальных пользователей, которые за месяц хотя бы раз залогинились / сгенерировали / открыли витрину** (считаем в штуках людей, не в рублях). Пример: MAU = 2 000 → за месяц продуктом пользовались две тысячи человек. |
| **DAU** | *Daily Active Users* — то же за **сутки** (в этом доке почти не используем). |
| **Валюта костов** | Все суммы с **`$`** — **доллары США (USD) в месяц**, если не сказано иначе. Так удобнее стыковать цены Replicate/fal/OmniRoute (они в USD). |
| **Рубли** | Для кассы в РФ: `₽ ≈ $ × курс` (ориентир планирования: зафиксировать курс в таблице, напр. **1 USD = 90 ₽**, и пересчитывать раз в месяц). Yandex Cloud в консоли часто в ₽ — при сверке фактуры переводите в USD тем же курсом или ведите колонку в ₽ отдельно. |
| **$/MAU** | Сколько в среднем долларов инфраструктуры и медиа приходится **на одного активного пользователя в месяц** (`C_total ÷ MAU`). |

## 1. Продукт, которого пока нет

Три опоры маркетплейса:

| # | Модуль | Суть |
|---|--------|------|
| 1 | **Профили креаторов** | Креатор генерирует (видео/картинку), публикует в свой профиль как «работу» / «модель стиля» / пресет |
| 2 | **Публичная витрина креативов** | Лента/галерея работ, которые можно **скачать** (или взять лицензию) |
| 3 | **Генерации** | На старте — **только бесплатные** (или почти бесплатные) модели видео через OmniRoute |

Цель фазы 0–1: **набрать трафик и UGC в минус** (субсидия генераций + хостинг превью), потом монетизировать поверх аудитории.

## 3. Разбор костов (структура P&L)

Все цифры с **`$` ниже — USD/мес** (см. блок «Как читать цифры» в начале).  
Цены storage/egress — порядок величины по Object Storage; в Yandex Cloud сверять фактуру (часто в ₽) и при необходимости делить на курс.

### 3.1. Фиксированные vs переменные

| Класс | Статья | Драйвер | Старт (0–1k MAU) | Как растёт |
|-------|--------|---------|------------------|------------|
| **Fixed** | VM / VPS (Flask + workers + Redis + OmniRoute) | тариф машины | $25–80 | ступенями (апгрейд RAM/CPU) |
| **Fixed** | Домен, TLS, мониторинг, бэкапы БД | — | $5–20 | слабо |
| **Fixed** | Время фаундера / поддержка | часы | «бесплатно» / opportunity | линейно от тикетов |
| **Semi-fixed** | OmniRoute process (Node) | RAM/CPU на той же VM | входит в VM | отдельный инстанс после ~5–10k MAU |
| **Variable** | Upstream video API (paid) | секунды видео × $/s | **$0** на free-path | **линейно** от paid gens |
| **Variable** | Object Storage (GB) | объём медиа | $1–10 | линейно от published + drafts |
| **Variable** | Egress / CDN | GB скачиваний + превью | $5–50 | **суперлинейно** при вирусной витрине |
| **Variable** | Watermark / transcode CPU | CPU-сек на publish | ≈$0 на малой VM | упирается в CPU → очередь или worker |
| **Variable** | Модерация / abuse | жалобы, баны | 0–0.2 FTE | скачет при росте UGC |
| **Risk** | Fallback на paid API при падении free | outage veoaifree | $0 | внезапно: $100–1000+/день |

### 3.2. Себестоимость одной единицы

**Базовые допущения MVP (free-path):**

| Параметр | Значение |
|----------|----------|
| Длина клипа | 5 с |
| Размер mp4 (сжатый 720p) | ~8–15 MB → берём **12 MB** |
| Превью / thumb | ~0.3 MB |
| Publish rate | 20% gens → в витрину |
| Просмотров превью на 1 published / мес | 30 (лента) |
| Скачиваний на 1 published / мес | 3 |
| Free API $/gen | **$0** (veoaifree / Agnes) |
| Retry overhead | ×1.3 к числу upstream-вызовов |

| Единица | Формула | Оценка $ |
|---------|---------|----------|
| 1 free gen (успех) | API $0 + ~CPU очереди ≈0 | **~$0.00–0.01** |
| 1 published creative (хранение 1 мес) | 12.3 MB ≈ 0.012 GB × $0.02 | **~$0.00025** |
| 1 published (год хранения) | ×12 | **~$0.003** |
| 1 download оригинала | 0.012 GB × $0.015 egress | **~$0.0002** |
| 30 превью в ленте | 30 × 0.0003 GB × egress | **~$0.0001** |
| **Итого «жизнь» 1 published / мес** (хран. + 3 DL + превью) | | **≈ $0.001–0.002** |
| 1 **paid** gen Wan 5s @ Replicate | 5 × $0.025 | **$0.125** |
| 1 paid Seedance 2.0 5s @ Replicate | 5 × $0.10 | **$0.50** |

Вывод: на free-path **маржинальный кост UGC ничтожен**, пока не включаем paid API и пока egress не взрывается. Главные деньги жрёт **инфра ступенями** и **трафик витрины**, не «цена генерации».

### 3.3. Лимиты фазы «минус» (чтобы косты были предсказуемы)

| Правило | Значение | Эффект на косты |
|---------|----------|-----------------|
| Free gen / день / аккаунт | **4** | caps variable load |
| Free gen / час / IP | ≤ 6 (upstream) | caps concurrent |
| Concurrent jobs глобально | очередь, max N in-flight | caps CPU/RAM workers |
| Publish | после gen + лицензия | меньше orphan storage |
| Анонимный download | watermark + rate limit | caps egress |
| Draft TTL | удаление через 14–30 дней | caps storage |
| Новый аккаунт | email verify | caps abuse gens |

## 4. Вычислительные мощности (что реально крутится у нас)

Генерация видео на free-path идёт **на чужих серверах** (veoaifree / Agnes). У нас — оркестрация, очереди, раздача файлов. GPU у себя = отдельный сценарий (дорого).

### 4.1. Компоненты и нагрузка

| Компонент | Роль | Ресурс | Нагрузка от пользователей |
|-----------|------|--------|---------------------------|
| Flask API | HTTP, auth, catalog, chat proxy | CPU + RAM | RPS страниц + API |
| Redis | inbound + channel queues | RAM | ∝ длина очереди × payload |
| worker-dispatcher | маршрутизация job | CPU низкий | ∝ jobs/мин |
| worker-omni (video) | poll OmniRoute video API | CPU + сеть + RAM на буфер файла | ∝ in-flight gens |
| worker-repl / fal | later paid | то же | ∝ paid jobs |
| OmniRoute (Node :20128) | router / free providers | RAM 0.5–2 GB+, CPU | ∝ concurrent upstream |
| Object Storage | media | почти без CPU у нас | GB + egress |
| Postgres/SQLite | профили, creatives | диск + RAM | ∝ rows |
| Watermark / ffmpeg | при publish | **CPU-heavy** | ∝ publishes/мин |

### 4.2. Профиль машины (ступени)

| Ступень | MAU (ор.) | Конфиг (ориентир) | Что держит | $/мес (ор.) |
|---------|-----------|-------------------|------------|-------------|
| **S0** | 0–500 | 2 vCPU / 4 GB / 40 GB SSD | Flask+Redis+1 worker+Omni на одной VM | $20–40 |
| **S1** | 500–3k | 4 vCPU / 8 GB | + отдельный worker process, очередь без swap | $40–80 |
| **S2** | 3k–15k | 4–8 vCPU / 16 GB **или** 2 VM (app + workers) | ffmpeg watermark не блокирует API | $80–200 |
| **S3** | 15k–50k | app VM + worker VM + managed Redis | CDN перед storage | $200–500 |
| **S4** | 50k+ | горизонтальные workers, CDN, возможно GPU-пул | paid API spend >> infra | $500+ **+ API** |

**GPU (свой Comfy/SD):** 1× RTX 4090 / cloud A10 ≈ **$0.5–2/час** ≈ $300–1500/мес при 24/7. Имеет смысл только если free upstream умер **и** unit-экономика paid API хуже своего GPU. На старте — **не брать**.

### 4.3. Пропускная способность очереди (без своего GPU)

Upstream free ≈ **6 req/hour** на источник (осторожная оценка veoaifree).  
Даже при 10 «слотах» через ротацию/прокси (рискованно по ToS) потолок порядка **десятков gens/час**, не тысяч.

| Глобальный in-flight | Ожидание при 100 jobs в очереди | UX |
|----------------------|----------------------------------|-----|
| 2 | ~часы | waitlist / «ночная очередь» |
| 6 | десятки минут | приемлемо early |
| 20+ | только если несколько устойчивых free/paid каналов | иначе ToS-ban |

**Практический потолок MVP:** проектировать продукт под **≤ 200–500 успешных free gens/день** суммарно, пока нет paid fallback. Выше — waitlist, лотерея слотов, или платный fast-lane.

### 4.4. Когда упираемся не в API, а в нашу CPU

Watermark + remux (ffmpeg) ~5–20 CPU-sec на клип.  
На 2 vCPU: грубо **5–15 publishes/мин** пик, иначе растёт очередь publish.

Формула:

```
publishes_per_min_capacity ≈ (vCPU_eff × 60) / cpu_sec_per_publish
```

При 4 vCPU и 10 sec/clip ≈ **24 publish/min** теоретически; на практике с запасом под API — планировать **5–10/min**.

## 5. Зависимость костов от числа пользователей

**MAU** здесь = сколько **людей** за месяц реально пользовались продуктом (не выручка).  
**Косты в таблице** = **USD/мес**. Чтобы получить рубли: умножить на курс (пример: ×90 → ₽).

Пример: строка «MAU 2 000 · C_total ≈ $70» значит «при двух тысячах активных за месяц инфраструктура+медиа ≈ 70 долларов ≈ 6 300 ₽ при курсе 90».

### 5.1. Воронка → натуральные объёмы

Вводим **MAU** = месячные активные пользователи (уникальные люди).

| Коэффициент | Обозначение | Базовый сценарий |
|-------------|-------------|------------------|
| Доля генерирующих | g | 25% MAU |
| Gens / активный gen-юзер / мес | n | 8 (при лимите ~4/день реально меньше; берём 8) |
| Успех gen | s | 70% |
| Publish / успешный gen | p | 20% |
| Downloads / published / мес | d | 3 |
| Preview hits / published / мес | v | 30 |
| Размер файла | F | 0.012 GB |
| Thumb | T | 0.0003 GB |

```
G_attempt = MAU × g × n
G_ok      = G_attempt × s
P_pub     = G_ok × p
Storage_GB ≈ P_pub × (F+T) × life_months   # life_months=1 для «этого месяца», растёт накопительно
Egress_GB  ≈ P_pub × (d×F + v×T)
```

**Накопление storage:** если работы не удаляем,

```
Storage_GB(t) ≈ Σ_months P_pub_m × (F+T)
```

через 12 мес при стабильном P_pub storage ≈ **12×** месячного прироста.

### 5.2. $ от объёмов

```
C_api_free   = 0
C_api_paid   = G_paid_ok × seconds × $/s
C_storage    = Storage_GB × $per_GB_month
C_egress     = Egress_GB × $per_GB_egress
C_infra      = step_function(MAU)     # см. §4.2
C_total      = C_api_* + C_storage + C_egress + C_infra + C_ops
```

**Переменный кост на 1 MAU (free-path, без накопления годами):**

```
≈ (g×n×s×p) × [ (F+T)×$storage + (d×F+v×T)×$egress ]  +  C_infra/MAU
```

При базовых коэффициентах publish на MAU ≈ `0.25×8×0.7×0.2 = 0.28` работы/мес/MAU  
→ variable media ≈ **$0.0005–0.001 / MAU** + **C_infra/MAU**.

На S0 ($40) при 500 MAU infra = **$0.08/MAU**; при 50 MAU = **$0.80/MAU**.  
Пока аудитория мала, **доминирует фикс**; после нескольких тысяч — egress + ступени VM; после включения paid gens — **API**.

### 5.5. Чувствительность (что сильнее всего двигает $)

| Рычаг | +10% к параметру | Эффект на C_variable |
|-------|------------------|----------------------|
| MAU | — | почти линейно на media; ступени на infra |
| n (gens/юзер) | +10% | +10% попыток → очередь / API |
| p (publish rate) | +10% | +10% storage+egress |
| d (downloads) | +10% | +~10% egress (главный variable после API) |
| F (размер файла 1080p) | +50% | +50% storage+egress |
| Включение paid share | с 0→10% | скачок C_api на порядки vs media |
| Накопление storage 12 мес | ×12 к storage | C_storage растёт даже при плоском MAU |

### 5.6. План управления костами по порогам пользователей

| Порог MAU | Триггер | Действие |
|-----------|---------|----------|
| 0 | launch | S0, только free models, лимит 4 gen/день, draft TTL 14 дней |
| 300 | очередь > 30 мин p50 | явный waitlist + статус «место в очереди» |
| 1 000 | egress > $20/мес | CDN + лимит anon DL + сжатие превью |
| 3 000 | CPU watermark > 70% | вынести ffmpeg на отдельный worker / VM S2 |
| 5 000 | free upstream rejects ↑ | не субсидировать paid; продавать кредиты (фаза B) |
| 10 000 | storage > 100 GB | lifecycle: холодное хранение / сжатие старых |
| 20 000+ | — | S3+, CDN обязательно; infra уже << потенциального API burn |

### 5.7. Burn-модель (полная)

```
C_month =
  C_infra(MAU)                                          # ступень §4.2
+ Storage_GB_cumulative × $storage
+ Egress_GB(MAU, p, d, v, F) × $egress
+ G_paid_ok × sec × $/s                                 # 0 на фазе A
+ C_ops(tickets ≈ k × MAU)                              # время/аутсорс
+ C_risk_buffer                                         # 10–20% на ретраи и инциденты
```

При **только free upstream** до ~2–5k MAU: `C_month ≈ C_infra` ($40–120).  
После вирусной витрины без CDN: растёт `C_egress`.  
После субсидии paid: растёт `C_api` линейно и быстро обгоняет всё.

## 6. Как монетизировать после трафика

Порядок включения (не всё сразу):

### Фаза A — аудитория и UGC (0–3 мес)
- Free video only (Seedance/VEO free path)
- Профиль креатора + публикация работ
- Витрина со скачиванием **с водяным знаком**
- Метрики: signup → first gen → publish → download чужой работы

### Фаза B — кредиты и качество (3–6 мес)
- Платные модели (Wan / Seedance 2 / Kling / Veo paid) за кредиты
- Снятие watermark / HD / без очереди
- «Boost» работы в витрине (реклама внутри продукта)

### Фаза C — маркетплейс (6–12 мес)
- Креатор ставит цену на скачивание / коммерческую лицензию → **take rate 15–30%**
- Подписка Про: лимиты + каталог моделей + analytics профиля
- B2B: студии покупают пакеты кредитов + white-label витрину

### Фаза D — сеть эффектов
- Подписка на креатора
- Пресеты/LoRA-подобные «стили» (если появятся) как платный ассет
- Affiliate: креатор приводит трафик → % с paid gens рефералов

**Правило:** не продавать то, чего нет в live-каталоге; ассистент уже заточен под «экономического адвоката» — использовать его для upsell честных альтернатив.

## 12. Резюме в одном абзаце

Стартуем как **бесплатная видео-песочница + соцвитрина креаторов**: генерации на free OmniRoute-путях (Seedance/VEO free, опционально Agnes). На free-path **маржинальный $ за gen ≈ 0**; до ~2–5k MAU доминирует **фикс VM ($30–120)**, потом egress/CDN и ступени CPU под watermark. Потолок — не «сколько юзеров», а **пропускная способность free upstream** (~сотни gens/день); выше — waitlist или платный fast-lane. Субсидия paid API даже на 10% gens быстро обгоняет infra. Монетизация (кредиты, watermark unlock, take rate) — после того, как витрина даёт удерживаемый трафик.
